Debugging Guide (compact)

Target execution:
- Prefer focused debug runs with `targetFlowBlockName` for diagnosing individual flow blocks.
- Use a full debug run when needed to verify the actual end-to-end result or complete the user's goal.
- Before starting a full run, set `maxProtocolEntries` to a reasonable limit to avoid excessive debug output; limit captured field-value changes with `maxCapturedFieldValueChanges` where appropriate.
- Before starting a full run, tell the user that a full run will be executed and which limits are applied. 
- After a full run, report `protocolEntryCountTotal` versus the number of returned protocol entries, warnings/errors, and the final result so truncation is transparent.
- For potentially expensive full runs (e.g. long runtime, many external requests, or writes to external systems), ask the user before running.
- When debugging a target flow block, include the target execution if the target block's own result fields are needed.
- If only predecessor output is needed, stop before the target to inspect incoming context.
- To start a result flow block at a specific dataset value, set its `StartValue` property before the focused debug/test run.

Result windowing:
- `BaseResultFlowBlock` supports output modes: `All`, `First`, `Last`, `Range`.
- `Range` can be controlled with `StartIndex`, `EndIndex`, and `StartValue`.
- Use these properties to inspect a specific result dataset instead of reading all results.
- With multiple result fields, `StartValue` matches when at least one result-field value in the dataset equals the configured start value.

Field-value limiting:
- Debug/test Tool API responses limit the total estimated tokens used by field values.
- The limiter is always applied to field values, even for focused result requests.
- Truncated values end with a short truncation marker.
- Complete field values may omit value metadata.
- Truncated or omitted values include navigation metadata such as start index, total length, and current returned length.
- `RunTestDefinition` only applies limiting; it does not support field-value windowing.
- `GetLastDebugArtefact` lists field changes and result datasets with limiting; it does not navigate inside large strings.
- For detailed navigation inside truncated or oversized debug field values, use `InspectFieldValue`.
- `InspectFieldValue.searchMode=StartAt` returns content starting at `searchIndex` or the first matched `searchValues` marker.
- `InspectFieldValue.searchMode=LookAround` treats `searchIndex` or the first matched `searchValues` marker as the center and returns context before and after it.
- For generated result datasets, `GetLastDebugArtefact` returns `resultDatasetCount`, `includedDatasetCount`, and whether later datasets were omitted due to the field-value token limit.
