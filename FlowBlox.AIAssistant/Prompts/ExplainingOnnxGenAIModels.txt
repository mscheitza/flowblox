ONNX Runtime GenAI model setup

Use only for `OnnxGenAIFlowBlock` setup or troubleshooting.

Distributed scripts (`GetDistributedData`, `dataType="python"`):
- CPU default: `download_phi4_mini_instruct_onnx.py` (about 4.9 GB).
- CUDA opt-in: `download_large_cuda_genai_model.py`. Mistral 7B INT4 is its default; `--model-id` also selects Phi-3 Medium 14B INT4 or DeepSeek R1 Distill Qwen 7B INT4. Use `--list-models` for exact IDs.
- Never propose, download or configure a CUDA model unless the user explicitly requests a larger/GPU model. Confirm download size and free disk space first.
- Create the managed system input file with `copyFromDistributedData={dataType:"python",fileName:<script>}`. It is materialized below `$Project::InputDirectory`.
- Command: `python "$InputFile::Path" --model-root-directory "$Options::AI.Onnx.GenAI.ModelRootDirectory"`. To run it, call only `ExecuteInputFileCommand`; it materializes the script first, while downloaded models go to the shared GenAI model root for reuse across projects.
- Default to automatic provisioning: set `executeBeforeRuntime=true` so the script ensures the model exists before FlowBlock initialization. Use one-time manual execution only when the user explicitly requests manual-only provisioning. Tell the user whether the script was configured for automatic runtime-start execution or must be run manually before starting the runtime.
- Scripts use `huggingface_hub`, default below the passed model root (default `%USERPROFILE%\.flowblox\onnx\genai`), validate required files and exit immediately when complete. `--output-directory` selects an exact folder.

Default behavior when the user did not specify a model:
- Do not ask for a model/folder. Run the CPU-default command above, keep provider `Default`, and use the preconfigured Phi-4 Mini Instruct template. It reuses or creates `$Options::AI.Onnx.GenAI.ModelRootDirectory\Phi-4-mini-instruct-onnx`, matching the FlowBlock default. Observe `explaining_input_files` confirmation rules.
- Only switch script, provider, `ModelFolder`, and chat template when the user explicitly requests another compatible model.

CUDA workflow:
1. Retrieve `detect_onnx_cuda_hardware.py` as a managed input file and execute `python "$InputFile::Path"` on demand; do not enable `executeBeforeRuntime`.
2. Continue only with explicit user approval and `cudaAvailable=true`. Follow `modelRecommendations`: Mistral/DeepSeek require at least 8 GiB VRAM (12 GiB preferable), Phi-3 Medium 16 GiB; all require Compute Capability 7.0+. Advise against `recommended=false`; detection never guarantees performance.
3. Retrieve and execute the selected CUDA script. Never pass `--skip-hardware-check` unless the user explicitly stages files for another CUDA machine.
4. Set option `AI.Onnx.Provider` to `CUDA` with `SetOptionValue`, then set the flow block's `ModelFolder` to the reported `MODEL_FOLDER` with `UpdateFlowBlock`.
5. Explain that the provider is application-wide, `AiExecutionProvider` reflects it, synchronized CUDA runtimes must exist, and FlowBlox must restart after a provider change.
If CUDA is unavailable or too weak, recommend `Default` plus a CPU package; never infer CUDA from Windows or a generic display adapter.

Requirements and configuration:
- Python must be available as `python`. If not recognized/found, direct the user to {{PythonDownloads}} and `PATH`; this is not an ONNX failure.
- Use a published ONNX Runtime GenAI package. `ModelFolder` must directly contain `genai_config.json`, its tokenizer and every referenced ONNX file; never mix checkpoints. Generic ONNX/Optimum export is insufficient without a valid GenAI package.
- Provider and model variant must match; changing the provider does not convert a model. Downloads may require Hugging Face authentication/license acceptance.
- CPU default: `$Options::AI.Onnx.GenAI.ModelRootDirectory\Phi-4-mini-instruct-onnx`.
- Configure `Prompt`, optional `SystemPrompt`, `UseChatTemplate` and `ChatTemplate`. Select the matching Toolbox template, for example `Phi-4 mini Instruct`, `Phi-3(.5) Instruct`, `Mistral 7B Instruct v0.2`, or `DeepSeek R1 Distill`; Llama 3 and Qwen also have dedicated entries. A mismatch can produce poor/empty output.
- Validate provider, latency, RAM/VRAM and output quality before production.

For input-file creation, confirmation, stdout/stderr and `executeBeforeRuntime`, use `explaining_input_files`.
