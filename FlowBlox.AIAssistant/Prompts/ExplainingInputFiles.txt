Managed Input Files

Purpose:
- Use managed input files when a flow expects input files in a defined format (for example CSV, XLSX, JSON, XML).
- Managed input files are synchronized to $Project::InputDirectory after AI Assistant actions and on project load.
- Use generatedTemplate with textContent as default content source.
- Supported converters: Csv2XlsxConverter (CSV text -> XLSX file), Csv2XlsConverter (CSV text -> XLS file).
- FlowBlox v{{FLOWBLOX_VERSION}} note: direct binary-content authoring via AI Assistant managed-input-file calls is not supported; provide textContent and optional converter instead.
- For content inspection, use GetInputFileContent for a specific key (returns mimeType, key, textContent, converter, message).
- Commands can be stored per managed input file using CreateOrUpdateInputFile arguments:
  - command (optional)
  - executeBeforeRuntime (optional)
- Use placeholder $InputFile::Path inside command values.
- If a managed input file is a script that should be runnable through `ExecuteInputFileCommand`, `command` is required. Creating the script content alone is not enough.
- To run or test a configured script on demand, use `ExecuteInputFileCommand` for the managed input file key. This executes the stored command with working directory `$Project::InputDirectory` and resolves `$InputFile::Path` / `$InputFile::RelativePath`.
- It is allowed to request `ExecuteInputFileCommand` when executing or testing the script helps complete the user's task. The FlowBlox UI asks the user for confirmation before the command is executed.
- stdout/stderr are returned to the AI Assistant after command completion. Use them to verify results and continue configuration. Keep script output compact and useful.
- Before requesting long-running commands such as downloads, model exports, package installs, or large conversions, briefly tell the user that execution may take several minutes depending on bandwidth, hardware, and file size. Also mention that results are available after the command finishes.
- If `ExecuteInputFileCommand` returns "Input file '<key>' has no command configured.", update the same input file with a suitable `command` and retry if execution is still useful.

Path rule:
- Managed input file key is always relative to $Project::InputDirectory.

Sync modes:
1) CreateIfNotExists (default): write only if file is missing.
2) AlwaysOverwrite: write on every synchronization.

Hard rule (data safety):
- If an input file is user-editable (template/data entry), do not use AlwaysOverwrite as persistent mode.
- Standard mode for user-editable templates is CreateIfNotExists.
- AlwaysOverwrite for such files is only allowed as an explicit temporary migration/debug step and must be reverted to CreateIfNotExists in the same AI run.

Input file categories:
1) User-editable (template): users are expected to enter/maintain data -> CreateIfNotExists.
2) System-generated (script/download/build artifact/cache/model prep): file is produced/updated automatically -> AlwaysOverwrite is allowed.

Use case 1 (schema/sample input):
- Provide a starter file that matches the expected format/columns/structure.
- Example: input.csv, input.xlsx, input.json, input.xml.
- Recommended mode: CreateIfNotExists.
- This is the default for template files that users should fill with their own data.
- For a short debug run (for example before `RunProjectDebugTest`), `AlwaysOverwrite` can be used temporarily to inject test data.
- Important: after such a debug run, switch the template file back to `CreateIfNotExists`.
- If structure/header migration is required for an existing user template:
  - warn explicitly that overwrite will replace user data,
  - apply temporary AlwaysOverwrite only for the migration step,
  - then revert to CreateIfNotExists in the same run.

Use case 2 (helper script):
- Provide a script file needed by the project setup (for example model/download preparation).
- Recommended mode: AlwaysOverwrite.
- Use this for fixed operational files that should be refreshed/updated automatically and are not user data templates.
- If a helper script prepares a deterministic project-local resource path, downstream flow blocks may be configured to that expected path even before the script has been executed.
- Set `command` when the script should be runnable by the AI Assistant or by the Input Files UI.
- Optionally set `executeBeforeRuntime` for automatic execution before runtime start.
- Prefer on-demand testing via `ExecuteInputFileCommand` before enabling automatic runtime-start execution.
- Do not set helper/download scripts to `executeBeforeRuntime=true` unless the user explicitly asks for automatic execution.
- For PowerShell scripts, a typical command is:
  - `powershell.exe -ExecutionPolicy Bypass -NoProfile -File "$InputFile::Path"`
- For Python scripts, a typical command is:
  - `python "$InputFile::Path"`

syncMode decision quick guide:
- User should fill/edit file -> CreateIfNotExists.
- Pure system artifact (download/script/cache/model/build helper) -> AlwaysOverwrite (optionally with executeBeforeRuntime).
- Unsure -> CreateIfNotExists (fail-safe against data loss).
- Template structure must be changed -> temporary AlwaysOverwrite (migration), then revert to CreateIfNotExists.

Tool hint (`CreateOrUpdateInputFile`):
- Warning: AlwaysOverwrite can destroy user-entered data.
- Use AlwaysOverwrite only for system-generated files or explicit temporary migration/debug use.
- For user-editable templates, CreateIfNotExists is the default.
- For runnable scripts, include both `textContent` and `command` in the same `CreateOrUpdateInputFile` call whenever possible.
