ONNX extractive QA model setup

Use only for `OnnxQAFlowBlock` setup or troubleshooting.

Distributed script:
- Create the managed system input file from `copyFromDistributedData={dataType:"python",fileName:"export_onnx_qa_model.py"}`. Use `GetDistributedData(dataType="python")` to discover available filenames. The script is materialized below `$Project::InputDirectory`.
- Command: `python "$InputFile::Path" --model-root-directory "$Options::AI.Onnx.QA.ModelRootDirectory"`. To run it, call only `ExecuteInputFileCommand`; it materializes the script first, while the exported models go to the shared QA model root for reuse across projects.
- Default to automatic provisioning: set `executeBeforeRuntime=true` so the script ensures the model exists before FlowBlock initialization. Use one-time manual execution only when the user explicitly requests manual-only provisioning. Tell the user whether the script was configured for automatic runtime-start execution or must be run manually before starting the runtime.
- It defaults to `timpal0l/mdeberta-v3-base-squad2`, installs/imports the required Hugging Face/Transformers/Optimum packages, exports and validates graph/tokenizer, stores below the passed model root (default `%USERPROFILE%\.flowblox\onnx\qa`), and exits immediately when complete.
- `--model-id` presets: `timpal0l/mdeberta-v3-base-squad2` (tokenizer `microsoft/mdeberta-v3-base`), `deepset/deberta-v3-base-squad2` (`microsoft/deberta-v3-base`), `deepset/xlm-roberta-base-squad2` (`FacebookAI/xlm-roberta-base`), and `deepset/gelectra-base-germanquad` (matching GELECTRA tokenizer). `--output-directory` overrides the exact folder.
- If `python` is not recognized/found, direct the user to {{PythonDownloads}} and `PATH`; this is not an ONNX failure.

Default behavior when the user did not specify a model:
- Do not ask for a model/folder. Run the command above without `--model-id`; it reuses or creates `$Options::AI.Onnx.QA.ModelRootDirectory\mdeberta-v3-base-squad2`, matching the FlowBlock default. Observe `explaining_input_files` confirmation rules.
- Only use `--model-id` when another model is explicitly requested; then set `ModelFolder` to that model's resulting directory.

Contract and configuration:
- Extractive QA returns a verbatim span from `Context`; large corpora require separate retrieval.
- Keep graph, config and tokenizer from one checkpoint. Inputs: `input_ids`, `attention_mask`, optional `token_type_ids`; outputs: `start_logits`, `end_logits`.
- Required: `model.onnx`, `config.json`, `tokenizer_config.json`, plus WordPiece `vocab.txt`, byte-level BPE `vocab.json` + `merges.txt`, or matching SentencePiece `.model`. A GenAI folder with `genai_config.json` is invalid.
- Provider runtimes must exist and match the hardware; provider selection does not convert a model.
- Default `ModelFolder`: `$Options::AI.Onnx.QA.ModelRootDirectory\mdeberta-v3-base-squad2`.
- Defaults: `MaxSequenceLength=384`, `DocumentStride=128`, `MaxAnswerLength=30`. Enable/calibrate `AllowNoAnswer` and `NoAnswerThreshold` only for compatible checkpoints.
- Validate language/domain, punctuation, non-ASCII text, long/sliding-window contexts, latency and memory.

For input-file creation, confirmation, stdout/stderr and `executeBeforeRuntime`, use `explaining_input_files`.
