# Explaining Generators

Use this only when the user explicitly asks to generate values from test results.
If generator/test setup is unclear, load deep-dive test catalog key `explaining_test_definitions_deep_dive` for compact end-to-end examples.
Terminology note:
- "Generator" means a value-generation strategy under `GenerationStrategies` (test-driven), not a dedicated generator flow block type.

Purpose of generators:
- Configure a flow block from test input/output evidence so that executing it with the referenced field values produces result dataset(s) that satisfy the defined test expectations.
- Run when required test execution fails or when explicitly triggered.

Standard test-driven + generator workflow (mandatory when the user requests this combination):
1. Build the flow successively only up to and including the first flow block that needs a generated selector, pattern, or other generated configuration.
2. Create and configure the required test definition for that target using `explaining_test_definitions` (do not duplicate or bypass its lifecycle rules).
3. Create/configure the compatible generation strategy on that target.
4. Call `RunGenerationStrategies` and let the configured generator produce the target value/configuration.
5. Inspect the generated configuration and test outcome. Once this stage works, extend the flow to the next generator-dependent block and repeat.
- Hard rule: the AI Assistant must not synthesize and write the selector/pattern/configuration itself in this workflow. `RunGenerationStrategies` is the authoritative generation step and also verifies that the generator setup functions.
- If generation fails, diagnose and correct the flow prerequisites, test evidence, expectations, or strategy configuration, then call `RunGenerationStrategies` again. Do not silently replace the generator with an assistant-authored value unless the user explicitly abandons the generator-driven approach.

Preconditions:
- Suitable test cases exist for the target flow block.
- A compatible generation strategy exists in the target flow block's `GenerationStrategies`.
- `AIPropertyValueGenerationStrategy` automatically uses every field referenced by the target FlowBlock, including field placeholders in field-enabled string properties and nested reactive objects. Password field values remain hidden.
- `SequenceDetectionGenerationStrategy` still has a required `InputField`; for its `SequenceDetectionFlowBlock` source this value is copied from the source and kept synchronized.
- Expectations describe the intended generator output and are explicit generation evidence, not only pass/fail assertions. Configure meaningful expected values/counts on each suitable target entry; AI property generation includes them in its generation prompt. Sequence Detection specifically requires an expected extracted value plus a `NumberOfDatasets` expectation.

Setup order:
0. Discover available generator types when unclear:
   - Call `GetSupportedTypes` with `baseTypeFullName="FlowBlox.Core.Models.Generators.FlowBloxGenerationStrategyBase"`.
   - Inspect selected strategy details with `GetTypeKindsInfo`.
1. Ensure test definitions exist and are connected/configured.
   Link test definitions via standard update logic, for example `UpdateFlowBlock` with `path=/TestDefinitions/Link` and value `{"resolveManagedObjectByName":"<testDefinitionName>"}`.
2. For runtime-start test execution with automatic regeneration, set `RequiredForExecution=true` on the used test definitions.
   Default AI behavior: do not set this flag automatically; set it only on explicit user request.
   Ask for enabling auto-regeneration only when generation strategies exist on the affected flow block.
3. Create/update generation strategy on the target flow block via `UpdateFlowBlock` at `GenerationStrategies` (exact property name).
   Important: `GenerationStrategies` is a FlowBloxReactiveObject collection (not a ManagedObject reference list), so do not use `/GenerationStrategies/Link`.
   Use path-based creation/update with typed index when needed, e.g. `/GenerationStrategies/0:FlowBlox.Core.Models.Generators.AIPropertyValueGenerationStrategy/...`.
4. Before detailed updates, call kind/type info tools (for example `GetTypeKindsInfo`) to confirm valid paths/options.
5. Configure only strategy details that are actually required. For `AIPropertyValueGenerationStrategy`, normally set its required `Provider` via the nested strategy path and keep the generated defaults described below.

`AIPropertyValueGenerationStrategy` standard path (strict):
- This strategy is supported on `BaseResultFlowBlock` targets and configures the target flow block automatically from the linked `FlowBloxTestDefinition` test evidence; it does not create or configure the test definitions themselves.
- Creating `AIPropertyValueGenerationStrategy` automatically initializes `PromptTemplate` from toolbox category `AIPromptTemplates`, entry `FlowBlox Quick Update Configurator`, and initializes `SystemInstruction` from `System - FlowBlox Quick Update JSON Output`.
- The default `FlowBlox Quick Update Configurator` prompt and Quick Update `SystemInstruction` already cover the complete configuration of the target flow block from its linked test data and expectations. Therefore, normally keep both defaults, set `Provider`, and call `RunGenerationStrategies`; adjust the prompts when the user explicitly requests custom prompting.
- Leave `AIPropertyValueGenerationStrategy.Temperature` unset (`null`) by default so the selected provider/model can apply its supported default; do not set it to `0` unless the user explicitly requests that value and the provider supports it.
- Because these defaults are assigned by the strategy constructor, `GetToolboxEntries` is normally unnecessary for setup. It remains available for explicit prompt customization or diagnosis of a missing/corrupt default.
- The default `FlowBlox Quick Update Configurator` resolves `$GenerationStrategy::TargetFlowBlockInputValues`, `$GenerationStrategy::TestExpectations`, `$GenerationStrategy::FlowBlockDescriptions`, `$GenerationStrategy::FlowBloxQuickUpdateSchema`, and `$GenerationStrategy::FlowBloxQuickUpdateFormat` from the target and its linked test runs.
- The AI provider returns the `FlowBloxQuickUpdate` JSON contract. `FlowBloxQuickUpdateFormat` then applies only schema-supported writable properties to the target flow block; omitted properties remain unchanged and supplied collections replace the existing collection completely.
- `RunGenerationStrategies` first executes all `FlowBloxTestDefinition` instances linked through the target's `TestDefinitions`. If at least one test fails, it runs the configured strategies with those test results and expectations, applies their generated configuration, and reruns the tests. If all tests already pass, no regeneration is needed.
6. Execute tests / runtime as requested by the user. For the standard test-driven + generator workflow, call `RunGenerationStrategies` at each successive generator boundary before building beyond it.
   Preferred troubleshooting sequence: run `RunGenerationStrategies` first; only run `RunTestDefinition` when detailed test protocol/results are needed.

Generator evidence at the target flow block:
- Recommended value expectation: target `FirstValue` or `AnyValue`, operator `ComparisonOperator.Equals`, expected value provided.
- Tip: Instead of `AnyValue`, prefer selection mode `UserInput_ExpectedValue` when downstream flow blocks should continue execution, because it combines selection and expectation.
- Dataset-count expectation: target `NumberOfDatasets`, operator `ComparisonOperator.Equals`, expected count provided.
- These expectations are useful for every generator because they describe the intended result; more precise conditions usually improve generator quality. `NumberOfDatasets` is mandatory for Sequence Detection and useful output-shape context for other strategies.

Minimum test-case requirements:
- `AIPropertyValueGenerationStrategy`: at least 1 suitable `FlowBloxTestDefinition` linked to the target.
- `SequenceDetectionGenerationStrategy`: at least 2 suitable `FlowBloxTestDefinition` instances linked to the same target (the code reports these as automatically executed test cases). Multiple target rows inside one definition still count as one case for that target.

Sequence detection tip (complex hierarchical content such as hard-to-read DOM/web content):
- Use `SequenceDetectionFlowBlock` with `SequenceDetectionGenerationStrategy` when XPath/CSS/Regex/Start-End approaches are unstable or hard to maintain.
- `SequenceDetectionGenerationStrategy` is supported only on `SequenceDetectionFlowBlock` (`FlowBloxSupportedTypes`).
- Practical setup:
  1. Ensure at least 2 linked test definitions exist on the same `SequenceDetectionFlowBlock`.
  2. In every definition, ensure the automatically synchronized `InputField` receives a non-empty test value and the SequenceDetection entry contains expected value + `NumberOfDatasets` expectation for its single result configuration.
  3. Create/configure `SequenceDetectionGenerationStrategy` and run `RunGenerationStrategies`.
- Shared-branch optimization: two SequenceDetection sibling targets after the same WebEvent may reuse the same two test definitions. Link both definitions to both targets and configure each target row's own expected value/count. This avoids duplicate browser scenarios, but does not reduce the minimum below two definitions.
- Runtime-start auto-regeneration (`FlowBloxTestDefinition.RequiredForExecution=true`) is optional and can be expensive for WebBrowser/WebEvent chains.
- Default behavior: do not enable `RequiredForExecution` automatically; inform the user and enable only on explicit request.

Use-Cases / Examples:
1. Happy path (simple target property):
- Create `AIPropertyValueGenerationStrategy` in the target `BaseResultFlowBlock.GenerationStrategies` collection.
- Set its `Provider`; keep the automatically assigned `FlowBlox Quick Update Configurator` `PromptTemplate` and default Quick Update `SystemInstruction` unchanged.
- Call `RunGenerationStrategies`; failing linked tests supply the evidence and expectations used to generate and apply `FlowBloxQuickUpdate` configuration to the target flow block.
2. Special use-case (collection configuration):
- Example: `StartEndPatternSelectorFlowBlock.StartEndPatterns`.
- The Quick Update schema lists allowed collection item properties.
- The AI must return the complete collection in the `Properties` object; existing items are replaced.

Do not create or wire generators unless the user explicitly requests it.
